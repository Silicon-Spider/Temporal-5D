# Upstream reports (drafts)

These are drafts of reports to two of the pinned oracle projects, written for the project owner to file in each project's own issue tracker (register H27: defects as bug reports, disagreements with a documented rule as questions citing the source; drafted by the agent, filed by the owner). Nothing here has been filed yet. Each draft stands without this repository.

**Bug reports** (ruling R7 in `docs/rules/README.md`). Each gives a minimal reproduction, the expected and the actual output, the root cause at the pinned commit, and the rule cited from public sources. The evidence behind them is in `docs/checkpoints/checkpoint-1-check-clusters.md` ("Mate traces" and "Count trace"). Every reproduction was re-run against the pinned code on 2026-10-01: 5d-chess-js was loaded at its pinned commit, with its suggested fix also checked by applying it in memory, and ftxi was run as its stock `5dtools`, built from its pinned commit.

- `5d-chess-js-mate-search.md`: 5d-chess-js (`ee403c8`). Its exhaustive checkmate search hands `boardFuncs.moves()` a search-tree node instead of a board, so it reports checkmate where a legal turn exists.
- `ftxi-black-pawn-timeline-double-step.md`: ftxi/5dchess_engine (`2ea9f1b`, v0.4.10). Its move generator never gives a Black pawn or brawn the two-timeline double step, though it gives White's.

**A question** (the user's ruling on spec issue 126 at CHECKPOINT 8: "report it too, as a question citing the source and a few representative positions, not as a bug: if ftxi's author can show the game behaves ftxi's way, our rulebook is wrong and we want to know"). **Notation-reader gaps: two bug reports and a question** (2026-11-08; found by the done-means audit's verification of the ungated rulesets, `docs/BUILD_LOG.md` issue 579). Each is move text that the notation specification allows (adri326/5dchess-notation at the pin, `oracles/third_party/notation/README.md`, cited by line) and that an oracle cannot read, so it stops following a public record that the engine and penteract/cwmtt read to its end. Each refusal was reproduced on 2026-11-08 at the pinned commits, with the oracle's reader read at its pin:

- through the harness (`observe`; no golden file written);
- with the stock tool or library: ftxi's stock `5dtools`, and 5d-chess-js loaded at its pinned commit, with its suggested fix checked in a scratch copy.

The drafts:

- `ftxi-signed-timeline-labels.md` (bug report): ftxi/5dchess_engine (`2ea9f1b`). `match_absolute_board` compares a timeline's sign as written with ftxi's own rendering of each candidate move. So `(+1T10)` in an odd game matches no move, and `(1T1)` in an even one; the notation allows both, and so does ftxi's own grammar (`<line> ::= ['+' | '-'] <natural-number>`). This is KD-0054 (cwmtt/tesseractMageOChicken, action 28), whose `upstream` names the draft. A defect: the oracle's grammar and its 5DFEN reader take the sign, and its matcher does not.
- `5d-chess-js-signed-timeline-token.md` (bug report): 5d-chess-js (`ee403c8`). The reader removes `(>Lx)` with `/\(>L\-?\d*\)/g`, so `(>L+1)`, the form the notation's own example game writes, is read as a move and fails the whole import (cwmtt/tesseractMageOChicken, White's 13th turn). The text is in the notation version the library's documentation names (92c68f0) as well as at the pin. No known divergence records it, and none is needed: the library's outcome is `unsupported`, not `rejected`, and the comparison counts only a rejected run's refused action as a legality disagreement (`observations.refused_action`), so the library simply answers nothing from that turn on. A defect: the reader means to drop the token and misses one of its forms.
- `ftxi-empty-last-sub-turn.md` (question): ftxi/5dchess_engine (`2ea9f1b`). A last sub-turn with no moves is refused, whether it is followed by a result - `/ 1-0`, as the notation's example game ends - or by nothing (cwmtt/brawnsPuzzles-another, `4. We3 /`). A question, not a bug: ftxi's own grammar requires a move after every `/`, so its reader does what its documentation says, and the notation shows the form by example, not by rule. The answer also tests our own reading (the engine drops an empty last action). Like Chess in 5D's refusal above, this one is `unsupported`, so it needs no known-divergence entry.
